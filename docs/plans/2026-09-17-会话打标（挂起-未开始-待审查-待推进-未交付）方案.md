# 会话打标（挂起 / 未开始 / 待审查 / 待推进 / 未交付）方案

> 状态: 已落地 | 最后核对: 2026-09-17

## 一、目标

在会话栏（左侧项目/会话列表）为单个会话提供「打标」能力：

1. 会话右键菜单 / 「…」菜单新增「标记」二级菜单，可选 5 个状态：挂起、未开始、待审查、待推进、未交付，并支持取消标记。
2. 被标记的会话自动进入置顶区；取消标记后自动回到普通区。
3. 标记不影响既有「单独置顶」功能，两者共存。
4. 标记会话的置顶图标使用该标记的独立配色，与普通置顶（品牌色）一眼可区分。
5. 会话筛选器新增「标记」筛选：全部 / 已标记 / 未标记 / 5 个具体状态。
6. 会话行右侧悬浮信息卡（hover card）在标题行右侧（同一行、靠右上角）展示带标记配色的状态标签（色点 + 标记名称），未标记会话不出现该标签；标题折行时标签停在首行右侧，标签自身垂直中心与标题首行文字中心严格对齐（实测偏移 0px）。

## 二、核心设计

| 决策 | 说明 |
| --- | --- |
| 存储位置 | 会话 `metadata_json` 中的 `sessionLabel` + `labeledAt`，**不新增列、无迁移**（与 `debugMode` / `fastMode` 同策略） |
| 置顶语义 | **不改写 `pinned_at`**。渲染端统一谓词 `isSessionPinnedZone(session) = pinnedAt != null \|\| sessionLabel != null` 推导「进置顶区」 |
| 置顶区内排序 | 有效置顶时间 = `pinnedAt ?? labeledAt`（手动置顶时间优先），倒序；刚打标的会话因此立刻浮到置顶段顶部 |
| 手动置顶互斥提示 | 已标记会话的「置顶 / 取消置顶」菜单项置灰，并在条目下给出「已标记，自动置顶」说明，避免「点了取消置顶却仍在顶部」的矛盾状态 |
| 视觉区分 | 标记会话的置顶图标按标记配色渲染（`session-pin-wrap label-<key>`），悬浮给出「<标记>（已标记，自动置顶）」；未标记置顶保持原样式不变 |
| 悬浮卡标签 | 会话行 hover 卡（`SessionHoverCard`）标题行内、标题右侧增加标记标签（标题行改 flex 布局：标题 `flex: 1 1 auto`、标签 `flex: 0 0 auto` 贴右上角），与置顶图标、筛选器色点共用同一份标记色板；未标记时不渲染，回归面为零 |
| 悬浮卡标签的尺寸与对齐 | 标签紧凑化：10px 字号、`padding: 0 6px`、色点 5px、`gap: 4px`、`box-sizing: border-box`，实测 53 × 15.6px。对齐不靠 margin 微调：标签高度取标题首行行盒高度（less 变量 `@hover-card-title-font-size * @hover-card-title-line-height` = 15.6px），`align-items: flex-start` 下标签中心与首行文字中心天然重合；编辑态行高由输入框决定，改用 `align-self: center` 与输入框文字中心重合 |
| 筛选与拖拽 | 标记筛选会隐藏部分会话，因此纳入 `canReorderSidebarSessions` 的阻断条件（与状态 / 计划任务筛选同口径） |

## 四、行为契约

- 标记只写 metadata：打标不会修改 `pinned_at`，手动置顶开关也不会清除标记。
- 取消标记：`sessionLabel` 与 `labeledAt` 同时置空，会话立刻回到普通段；若同时存在手动置顶则留在置顶区。
- 置顶区内的拖拽仍然只在同类（置顶区 vs 普通区）之间生效，标记会话与手动置顶会话共享置顶区的手动序。
- 「标记」筛选生效时禁用会话/项目拖拽排序（该筛选会隐藏会话）。
- 悬浮卡始终显示标记标签（编辑标题态同样保留，输入框改为 `flex: 1 1 auto; width: auto` 让出标签宽度），由于是只读展示，不参与任何筛选或置顶判定。
- 标签垂直位置由标题排版变量推导：标题字号或行高变化时，标签高度随之变化，中心对齐关系不会失效（无需重新调 margin）。
- 未标记且未置顶的会话行为与改动前完全一致（回归面收敛在这条不发生变化的路径上）。

## 五、验证

- 单测：`session-labels.test.ts`、`session-sidebar-sort.test.ts`、`SidebarFilterMenu.test.ts`、`SessionLabelMenu.test.tsx`、`SessionLabelTag.test.tsx`、`SidebarSessionList.test.tsx`（含 hover 打开悬浮卡后标签存在且与标题同行的用例）、`SessionSidebarContext.test.tsx`、`packages/agent-runtime` 的 `session-label.test.ts`（DB 往返）。
- 定向 typecheck：`packages/protocol`、`packages/agent-runtime`、`apps/desktop`。
- 悬浮卡标签几何量测（真实编译后的 less 产物 + 同版本 Chromium，按组件真实 DOM 搭最小页面量 `getBoundingClientRect`）：
  - 短标题：标签 53 × 15.59px、字号 10px，与标题首行文字中心偏移 **0px**（改动前 60 × 20.5px、11px、偏移 3.45px）。
  - 两行长标题：标签仍停首行，中心偏移 0px；标题行高 31.19px（两行），标签不参与撑高。
  - 编辑标题态：输入框行高 19.59px，标签中心与输入框文字中心偏移 0px。
  - 未标记会话（回归对照）：标题行 15.59px，与改动前一致，无标签节点。
  - 副作用：标记会话的悬浮卡标题行由 21.5px 降到 15.59px，卡片更紧凑。
- 未覆盖：真实界面观感（配色、二级菜单展开位置、标签在暗色主题下的对比度）需在 `pnpm dev` 实例中人工确认。
